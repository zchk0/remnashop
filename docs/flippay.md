# FlipPay

Интеграция по [документации FlipPay](https://flippay.pro/docs).

После обновления приложения применяется миграция `0055`, а при запуске в списке
платёжных систем появляется выключенная касса FlipPay.

В панели бота откройте «Платёжные системы → FlipPay» и заполните:

- `api_key`: публичный ключ `pk_…` из «Настройки и API → Интеграция и API».
- `api_secret`: секретный ключ `sk_…` из того же раздела.
- `webhook_secret`: отдельный секрет из «Настройки и API → Уведомления».
- `payment_method`: числовой ID метода; по умолчанию `100` — СБП. В документации
  также указаны `101` — карты МИР и `103` — криптовалюта. Актуальные подключённые
  методы и минимальные суммы возвращает `GET /api/v1/payment-methods` с ключами кассы.
- `payment_timeout_minutes`: время ожидания оплаты в боте, целое число минут
  больше нуля. По умолчанию — `30`; сброс настройки возвращает `30`.
  Изменение применяется ко всем ещё ожидающим (`PENDING`) платежам FlipPay,
  в том числе созданным до изменения настройки. Проверка выполняется раз в минуту.
  У остальных платёжных систем срок остаётся `30` минут. Срок действия ссылки
  на стороне FlipPay эта настройка не продлевает.

В кабинете FlipPay сохраните Callback URL из настроек бота:

```text
https://<APP_DOMAIN>/api/v1/payments/flippay
```

Затем включите кассу. Валюта — RUB, сумма передаётся строкой с двумя знаками после
точки. Покупатель переходит на `pay_url`, который вернул FlipPay; домен платёжной
страницы может отличаться от `flippay.pro`.

Вебхук проверяется по HMAC-SHA256 исходного тела и `X-Signature`. До постановки
задачи на начисление сверяются ID заказа, платёжная система, сумма без комиссии
покупателя и валюта. `success` подтверждает покупку, `failed` отмечает ошибку или
истечение срока, `refunded` отмечает возврат. Возврат сам по себе не отзывает
подписку — это общее поведение обработчика платежей проекта.

Если бот уже отменил ожидание и сохранил `CANCELED`, поздний подписанный `success`
не меняет этот статус и не начисляет покупку. Восстановление такой транзакции
разрешено только администратору через кнопку «Перепроверить оплату» после сверки API.
Повторное подтверждение уже завершённого платежа не начисляет покупку заново.
При временной ошибке или ещё не сохранённой транзакции endpoint возвращает `503`,
при неверной подписи — `403`, при некорректном содержимом — `400`.

В карточке обычной транзакции доступна «Перепроверить оплату»: бот запрашивает
`GET /api/v1/payments/{order_id}` и применяет покупку только после подтверждения
`success` и сверки данных. Действие требует права редактировать подписки.

У FlipPay нет отдельной песочницы. Автоматические тесты используют имитацию API;
проверку реальной оплаты выполняют после настройки ключей и публичного HTTPS callback.
