# Rivara Pay

Интеграция по спецификации Rivara Pay v1 от 6 ноября 2026 года:
https://rivarapay.io/docs.

После обновления выполните миграции (`alembic -c src/infrastructure/database/alembic.ini upgrade head`) штатным способом
запуска проекта. Миграция `0057` добавляет тип кассы и поле внешнего ID платежа.
При запуске бот создаст выключенную кассу Rivara Pay с валютой RUB.

В панели бота откройте платёжные системы → Rivara Pay. Задайте `api_key`
(скоупы `payments:read` и `payments:write`) и `webhook_secret`, затем включите кассу.
Секреты сохраняются с существующим шифрованием настроек касс.

В кабинете Rivara Pay создайте webhook с URL из настроек кассы бота
(`/api/v1/payments/rivarapay`; используйте скопированный URL, включая ваш домен
и фактический префикс). Подпишитесь на `payment.paid`, `payment.canceled`,
`payment.expired`. Секрет именно этого адреса укажите в `webhook_secret`.

В разделе «Методы оплаты» доступны два варианта:

- «Rivara Pay — все способы» включён по умолчанию: `allowedMethods` не передаётся,
  способ выбирается на странице Rivara Pay.
- Отдельные кнопки СБП (`SBP`), карты РФ (`CARD_RU`), международные карты
  (`CARD_INTERNATIONAL`), криптовалюта (`CRYPTO`): можно включить любую комбинацию.
  Каждая кнопка передаёт только свой тип в `allowedMethods`.

Включение общего варианта выключает отдельные кнопки; включение отдельного
метода выключает общий вариант. Названия всех кнопок можно менять и сбрасывать.
Доступность рельсов определяется настройками магазина в Rivara Pay; отдельного
API для загрузки доступных методов в документации нет.

В публичном API кабинета методы доступны в `payment_methods` предложений касс:
`id` — тип, `title` — настроенное название. В запросах покупки, продления
и покупки пробного тарифа передаётся `payment_method` с выбранным `id`.
Если включён только один вариант, поле можно не передавать.

Почта покупателя в Telegram передаётся как `<telegram_id>@telegram.org`,
как разрешено спецификацией; дополнительно спрашивать её не требуется.
Для пользователей без Telegram используется платёжная почта или почта аккаунта.
Интеграция отправляет покупателя на `checkoutUrl`; IP пользователя не подменяется
IP сервера, H2H QR специально не запрашивается.

Ключ `test_…` доступен для кнопки «Тест» в панели. Обычные покупки с таким ключом
отклоняются, тестовые webhook не выдают настоящую подписку. Кнопка «Тест» с
боевым ключом создаёт настоящий счёт, помеченный тестовым внутри бота.

Webhook проверяется по HMAC-SHA256 над временем и сырым телом, с окном ±300 секунд.
Перед передачей в очередь сверяются внутренний номер заказа, внешний `pi_…`,
сумма без комиссии покупателя, валюта и режим. Повторы дедуплицируются по
`X-Event-Id` в Redis; существующий атомарный переход статуса защищает от повторной
выдачи подписки. При ошибке очереди или ещё не сохранённом заказе возвращается
ошибка для повторной доставки. Запоздалое подтверждение оплаты обрабатывается
и после локальной отмены по таймауту.

Администратор может проверить оплату через существующую кнопку проверки платежа:
для Rivara используется сохранённый внешний ID и статус REST `SUCCEEDED`.
Переход по ссылке возврата сам по себе оплату не подтверждает.
